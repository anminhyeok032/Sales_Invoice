# 저장된 내역을 엑셀로 "똑같이" 보기 — 계획

> 상태: **구현됨 (2026-10-29)**. §6 결정은 모두 "동의"(보기 전용, 양식 시트 필요, 크기 증가 허용, 내려받기 + 자동 갱신 둘 다).
> 코드: 값 계산 `src/lib/excelView.js`·`src/lib/statementView.js`, 엑셀 쓰기 `src/lib/excelViewWriter.js`,
> 자동 갱신 `src/lib/transactionExcelSync.js`(공용 `src/lib/fileBackup.js`), 양식 칸 폭 `src/lib/printLayout.js`.
> 계획과 다른 점: 예전 형식 엑셀 백업 파일은 확인 없이 다음 저장 때 새 형식으로 덮어쓴다 — 앱 데이터에서 언제든
> 다시 만들 수 있는 사본이고, 새 형식이 예전 내용을 모두 포함하기 때문이다.
> 실제 거래처 이름·금액은 이 문서에 넣지 않는다.

## 1. 역할 나누기

| | JSON 백업 (1차) | 엑셀 파일 (2차) |
|---|---|---|
| 목적 | 앱 데이터를 **그대로** 보관·복원 | 앱 없이 엑셀에서 **앱과 같은 내용을 보기**·출력·집계 |
| 내용 | 앱이 가진 것 전부(id, 공급자/공급받는자 선택, 명세서별 수정, 합친 줄 원본, 합침 방식 등) | 사람이 읽는 값(실제 인쇄되는 상호·금액·품목) |
| 방향 | 앱 ⇄ 파일 (복원 가능) | 앱 → 파일 **한 방향** (엑셀에서 고쳐도 앱에 안 돌아옴) |
| 원본 여부 | 원본 | JSON/앱에서 언제든 다시 만들 수 있는 **보기용 사본** |

엑셀은 다시 불러오지 않는다. 두 곳을 원본으로 두면 어느 쪽이 맞는지 알 수 없게 된다.
엑셀 첫 시트 맨 위에 "보기 전용 — 여기서 고쳐도 앱에 반영되지 않습니다. 원본은 JSON 백업" 을 적는다.

## 2. 지금 엑셀 백업의 한계 (`src/lib/transactionExcelSync.js`)
- 시트 1개, 품목 한 줄씩 13칸(연도·월·거래처명·작성일자·항목날짜·품목·규격·단위·수량·단가·공급가액·세액·비고).
- 거래처명이 엑셀 업체 이름('가나')이라 **인쇄되는 공급받는자 상호와 다를 수 있음**. 공급자, 명세서별 수정값 없음.
- 명세서 단위 합계·목록이 없어 앱의 "저장된 내역 조회"와 같은 화면을 만들 수 없음.
- 숫자 서식·필터·틀 고정 없음(SheetJS 무료판은 셀 서식을 쓸 수 없다).

## 3. 새 엑셀 구성 (한 파일, 시트 여러 개)

### ① `목록` — 앱의 "저장된 내역 조회" 목록과 같은 표
| 칸 | 값 | 비고 |
|---|---|---|
| 작성일자 | 실제 날짜(엑셀 날짜) | 표시 `yyyy.mm.dd`, 정렬·기간 필터 가능 |
| 내용 | 첫 품목 + "외 N종" | 앱 목록과 같은 규칙 |
| 상호명 | **인쇄되는 공급받는자 상호**(명세서별 수정 반영) | 앱 목록과 같은 값 |
| 금액 / 세액 / 합계 | 숫자, `#,##0` | |
| 줄 수 / 장 수 | 인쇄 줄 수, 12줄 단위 장 수 | |
| 공급자 | 그 명세서로 찍히는 공급자 상호 | |
| 구분 | 앱에서 작성 / 기존 프로그램 / 필터 상태 저장 | |
| 명세서 ID | 품목 시트와 잇는 열쇠 | 맨 오른쪽, 좁게 |
- 첫 줄 틀 고정, 자동 필터, 맨 아래 합계 줄은 `SUBTOTAL(109, …)` — 엑셀에서 필터를 걸면 앱의 "조회 매출 합계"처럼 보이는 줄만 더해진다.

### ② `품목` — 인쇄되는 줄 그대로
명세서 ID · 작성일자 · 상호명 · No(인쇄 순서) · 날짜 · 품목 · 규격 · 단위 · 수량 · 단가 · 공급가액 · 세액 · 비고 · 구분(신작/수정) · 가공시간 · 합친 줄(원본 수)
- 비고는 **인쇄되는 그대로**(출력 설정의 일별 합계/메모 반영) 넣고, 원래 메모는 따로 한 칸.
- 합친 줄은 대표 줄 1줄(인쇄와 같음).

### ③ `합친 원본` — 합친 줄을 펼친 내용
명세서 ID · 대표 줄 No · 원본 순서 · 원본 줄의 모든 칸 · 합침 방식(수량/가공시간).

### ④ `거래처`, `공급자`
앱의 거래처 목록, 공급자(계좌번호 포함, 도장 이미지는 제외).

### ⑤ (선택) `명세서` — 한 장을 인쇄 양식 모양으로
명세서 전부를 양식 시트로 만들면 2,700장이 넘어 파일이 감당이 안 된다. 그래서:
- 저장된 내역 조회에서 고른 명세서 1건(또는 조회된 몇 건)을 **양식 모양 시트**로 내보내는 별도 단추.
- 테두리·보관용 색(파랑/빨강)·합계 줄 색·열 폭·A4 인쇄 설정·12줄 단위 나눔까지 앱 인쇄물과 맞춘다. 도장은 이미지로 넣는다.
- PDF가 이미 있으므로 우선순위는 낮다.

## 4. 만드는 방법
- **라이브러리**: 셀 서식(숫자 형식·테두리·채우기·글꼴), 틀 고정, 자동 필터, 수식, 인쇄 설정, 이미지가 필요하므로
  지금 쓰는 SheetJS 무료판으로는 안 된다. 후보:
  - **ExcelJS** (MIT): 위 기능 모두 지원. 앱 파일이 약 0.9MB 커진다(현재 약 0.73MB → 약 1.6MB). 권장.
  - `xlsx-js-style`(SheetJS 포크): 서식만 추가, 크기 증가는 작지만 수식·이미지·인쇄 설정이 약하다.
- **값 계산은 앱 화면과 같은 함수를 쓴다**: 목록 값은 History의 행 계산, 합계는 `computeTotals`, 비고는 `dailySumLabels`/출력 설정,
  공급자/공급받는자는 `resolveSupplier`·`matchReceiver`·`applyOverride`. 이를 `src/lib/excelView.js`(순수 함수:
  상태 → 시트별 행 배열)로 모아 단위 시험을 붙이고, 엑셀 쓰기(`excelViewWriter.js`)는 그 결과만 옮겨 적는다.
- **언제 쓰나**:
  - "엑셀로 내보내기" 단추(내려받기) — 언제든.
  - 기존 "엑셀 백업 연결"을 이 형식으로 바꿔, 연결해 두면 저장할 때마다 자동 갱신(JSON과 같은 방식).
    내역 2,700건·23,000줄이면 만드는 데 몇 초 걸릴 수 있어 마지막 변경 뒤 5초 모았다가 쓴다(측정 후 조정).

## 5. 단계
| 단계 | 내용 |
|---|---|
| 1 | `excelView.js`: 상태 → 목록/품목/합친 원본/거래처/공급자 행 계산 + 단위 시험(앱 목록 합계 = 엑셀 목록 합계, 품목 줄 수 = 인쇄 줄 수) |
| 2 | ExcelJS로 쓰기: 서식·틀 고정·필터·SUBTOTAL 합계·열 폭, "보기 전용" 안내 |
| 3 | "엑셀로 내보내기" 단추, 기존 엑셀 백업 연결을 새 형식으로 교체(옛 파일은 덮어쓰기 전에 확인) |
| 4 | 기존 프로그램 데이터 2,700건으로 크기·속도 측정, 자동 저장 간격 결정 |
| 5 | (선택) 명세서 1건 양식 시트 내보내기 |
| 6 | 실제 엑셀에서 열어 앱 화면과 대조(목록 건수·합계, 임의 명세서 10건 품목 대조) |

## 6. 결정 필요
1. 엑셀은 **보기 전용(한 방향)** 으로 두는 것에 동의하는지 — 엑셀에서 고친 것을 앱으로 다시 가져오고 싶다면 설계가 크게 달라진다.
2. 명세서 양식 모양 시트(⑤)가 필요한지, 목록·품목 표만으로 충분한지.
3. 앱 파일 크기 증가(약 +0.9MB) 괜찮은지.
4. 엑셀 백업 연결을 자동 갱신으로 둘지, 단추로 내려받기만 할지.
